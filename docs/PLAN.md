# ShibaPack 方案

跨平台软件安装包管理器。管理本机或 NAS 上的安装包文件，按软件、版本、文件三级整理，支持分类、收藏、智能分类、搜索、去重和一键运行。

## 已定的决策

| 项 | 决定 |
|---|---|
| 技术栈 | Tauri 2 + Rust + React 19 + TypeScript + Vite + Tailwind 4 |
| 存储 | 不用数据库。所有数据在用户指定的仓库根目录下，索引是根目录的 `software.json` |
| 多设备 | 不同步仓库文件夹，不做冲突合并 |
| 界面风格 | 参考 [Postflow](https://github.com/Wonvy/Postflow/)：深色默认、CSS 变量令牌、13px Inter、细分隔线、紧凑控件。只参考风格，不复制其源码（它是 GPL-3.0） |
| 强调色 | 默认蓝色，另有 4 种预设 |
| 布局 | 顶栏 + 侧栏（分类树）+ 中间栏（路由区）+ 详情栏 + 底栏，见下文 |

## 仓库文件夹

```
仓库根目录/                     在首次启动或“存储与备份”里指定
├─ software.json               唯一的索引：分类、软件、版本、文件、设置
├─ Visual Studio Code/         托管的安装包：软件名/版本号/原文件名
│  ├─ 1.96.2/
│  │  ├─ VSCodeUserSetup-x64-1.96.2.exe
│  │  └─ VSCode-darwin-universal.dmg
│  └─ 1.95.3/
│     └─ VSCodeUserSetup-x64-1.95.3.exe
├─ 7-Zip/
│  └─ 24.09/
│     └─ 7z2409-x64.exe
└─ .shibapack/
   ├─ backups/                 索引备份，最多 8 份
   ├─ trash/                   删除的托管文件先移到这里，30 天后清除
   ├─ cache/                   可随时删除
   └─ logs/
```

- 平台、分类、收藏都只是索引里的字段，不体现在目录层级里，修改它们不会移动文件。
- 两种存储模式：**托管**把文件复制进仓库；**索引**只记录外部文件的绝对路径，不动原文件。
- 托管文件保留原文件名。软件名和版本号由文件夹表达，索引丢失时可据此重建。
- 仓库之外只有一个引导文件（系统应用配置目录下的 `config.json`），仅记录仓库根目录在哪。

## 索引格式（`software.json`）

```json
{
  "format": 1,
  "categories": [{ "id": "…", "name": "开发工具", "parentId": null, "color": "#5aa2ff", "icon": "code" }],
  "software": [
    {
      "id": "…",
      "name": "Visual Studio Code",
      "publisher": "Microsoft",
      "homepage": "",
      "note": "",
      "categoryId": "…",
      "starred": false,
      "icon": null,
      "defaultVersionId": "…",
      "addedAt": "2026-11-19T12:00:00+08:00",
      "versions": [
        {
          "id": "…",
          "version": "1.96.2",
          "note": "",
          "addedAt": "…",
          "files": [
            {
              "id": "…",
              "name": "VSCodeUserSetup-x64-1.96.2.exe",
              "platform": "windows",
              "arch": "x64",
              "size": 109051904,
              "sha256": "…",
              "storage": "managed",
              "path": "Visual Studio Code/1.96.2/VSCodeUserSetup-x64-1.96.2.exe",
              "addedAt": "…"
            }
          ]
        }
      ]
    }
  ],
  "summaries": {},
  "settings": { "theme": "system", "accent": "blue", "language": "zh-CN", "defaultStorage": "managed" }
}
```

托管文件的 `path` 是相对仓库根目录的路径（统一用 `/`），索引文件的 `path` 是绝对路径。

保存流程：写临时文件 → 重新读入校验 → 轮转备份 → 原子替换。读取时若索引损坏，改名为 `software.json.corrupt` 并从最新可用的备份恢复。

## 界面布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏 h-11：Logo · ShibaPack     [ 搜索 ]          [↻ 检查更新] [+ 添加▾] │
├────────────┬───────────────────────────────┬─────────────────────────┤
│ 侧栏       │ 工具栏：标题 数量 [平台▾][安装状态▾] │ 详情栏（可收起）          │
│ 140–360px  │        ……… [分组][列表|网格|文件夹][⊟] │ 280–560px，默认 340      │
│ 全部软件   │ #/library    软件库            │ 头部：图标 名字 ☆ ⋯       │
│ 收藏       │ #/installed  已安装软件        │ 简介                      │
│ 有更新     │ #/storage    存储与备份        │ 安装状态 / 新版本         │
│ 已安装     │ 顶部 3px 导入进度条            │ 版本与安装包              │
│ 分类树     │                               │ ▸ 更多信息（分类、在线源、 │
│ 存储与备份 │                               │   主页、备注，默认收起）   │
│ 设置       │                               │                         │
├────────────┴───────────────────────────────┴─────────────────────────┤
│ 底栏 h-7：● 状态 | 软件数 | 安装包数 | 总大小 | 仓库路径 | v0.1.0 ↑    │
└──────────────────────────────────────────────────────────────────────┘
```

- 按功能分区：顶栏放全局的搜索、检查更新和“添加”（导入文件、导入文件夹、扫描建索引、整理根目录、从在线源添加都在这一个菜单里）；侧栏放导航和设置；列表工具栏左边是筛选、右边是视图。
- 两条拖拽手柄调整侧栏和详情栏宽度，宽度和详情栏的开合存 localStorage（只和本机有关的界面状态）。
- 软件列表的“版本”列：在线源上有更新的版本时，版本号右边有一个小箭头。底栏的 ShibaPack 版本号同理。
- 字号最小 12px。
- macOS 使用系统的红黄绿按钮（左上角），不显示自绘的窗口按钮；Windows 和 Linux 为无边框窗口加自绘按钮。

## 代码结构

```
crates/core/      与界面无关的核心逻辑，可单独测试
  model.rs        数据结构
  store.rs        读写索引、备份、恢复、统计、校验
  identify.rs     从文件名识别软件名、版本、平台、架构
  import.rs       导入、去重、扫描目录
  ops.rs          软件、版本、文件、分类、收藏的增删改
  classify.rs     智能分类：按软件名、发布者、简介推荐分类
src-tauri/        桌面外壳：命令、事件、窗口
src/              React 前端
  lib/            类型、接口封装、状态、国际化、浏览器预览用的模拟后端
  components/     通用组件、顶栏、侧栏、详情栏、对话框
  views/          软件库、已安装、存储
```

### 在线更新

ShibaPack 会更新自己：启动几秒后（之后每六小时）到 GitHub 上查有没有新版本，有就在后台下载、验证签名并安装。

- macOS 和 Linux 上可以在应用运行时装好，右下角提示“重启后生效”，点“立即重启”即可。
- Windows 的安装程序必须先关掉应用，所以下载完成后提示“安装并重启”，点了才装。
- 设置里可以关掉“自动更新”，也可以手动“检查更新”。
- Linux 上只有 AppImage 能自我更新，deb 和 rpm 装的要重新下载安装包。

它依赖三样东西：

| 东西 | 在哪 |
|---|---|
| 更新清单的地址 | `src-tauri/tauri.conf.json` 的 `plugins.updater.endpoints`，指向 `github.com/Wonvy/ShibaPack` 最新 Release 里的 `latest.json` |
| 验证签名用的公钥 | 同一处的 `pubkey`，可以公开 |
| 给更新包签名的私钥 | 开发机上的 `~/.tauri/shibapack-updater.key`，**不进仓库**；CI 里是仓库的 Secret `TAURI_SIGNING_PRIVATE_KEY` |

私钥丢了就没法再给已安装的用户推送更新（只能让他们手动重装），所以要另外备份一份。

验证情况：

- 在本机做过一次真实的演练：把更新地址临时指向本机，旧版 0.1.0 启动后自己发现了 0.1.1，下载、验签、替换了应用包，版本号变成 0.1.1。
- 发布版的自检确认更新检查能连到 GitHub 上的正式地址（目前还没有发布过版本，所以查不到更新）。
- 没有验证的：通过 GitHub Releases 的完整发布流程一次也没走过；Windows 和 Linux 上的更新没有试过。
